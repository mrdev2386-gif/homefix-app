**Root Cause:** Missing Cloud Function trigger that sends FCM notification when technician status changes to "approved".

## SOLUTION IMPLEMENTED

### File Created: `functions/src/technician/approval_notifications.ts`

```typescript
export const onTechnicianApproved = functions.firestore
    .document('technicians/{techId}')
    .onUpdate(async (change, context) => {
        const before = change.before.data();
        const after = change.after.data();

        // Check if status changed to "approved"
        const wasApproved = before.status === 'approved';
        const isNowApproved = after.status === 'approved';

        if (!wasApproved && isNowApproved) {
            // Send FCM notification
            await sendPushNotification(techId, 'technicians', {
                title: '✅ Profile Approved!',
                body: `Congratulations! Your profile has been approved. You can now create and list services.`,
                data: {
                    type: 'technician_approved',
                    screen: 'dashboard',
                },
            });
        }
    });
```

### Changes Made:

1. **Created:** `functions/src/technician/approval_notifications.ts`
   - New trigger: `onTechnicianApproved`
   - Listens to `status` field (correct field)
   - Sends FCM notification when status changes to "approved"
   - Includes error handling (notification is best-effort)

2. **Updated:** `functions/src/index.ts`
   - Added import: `import * as techApprovalNotif from './technician/approval_notifications'`
   - Added export: `export const onTechnicianApproved = techApprovalNotif.onTechnicianApproved`

### How It Works:

1. Admin approves technician in admin panel
2. Firestore document updated with `status: "approved"`
3. `onTechnicianApproved` trigger fires
4. FCM notification sent to technician's device
5. Technician receives notification: "✅ Profile Approved!"
6. Technician opens app
7. Firestore listener updates provider
8. UI shows approved status

## RELATED ISSUES FOUND (NOT FIXED - OUT OF SCOPE)

### Issue 1: Inconsistent Field Names

**Problem:** Code uses both `status` and `isApproved` fields:
- Admin panel sets: `status: 'active'`
- Cloud Function sets: `status: "approved"`
- Trigger checks: `isApproved` field
- Provider checks: `status == "approved"`

**Recommendation:** Standardize on single field (`status`) across all code.

### Issue 2: Trigger Watching Wrong Field

**File:** `functions/src/technician/triggers.ts`

Current code:
```typescript
if (before.isApproved !== after.isApproved) {
    // Syncs to services
}
```

Should be:
```typescript
if (before.status !== after.status && after.status === 'approved') {
    // Syncs to services
}
```

**Recommendation:** Update `syncTechnicianApprovalToServices` to watch `status` field.
