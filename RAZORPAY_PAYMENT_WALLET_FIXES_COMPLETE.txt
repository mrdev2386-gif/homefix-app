FIX 1: TRANSACTION SAFETY (CRITICAL)
────────────────────────────────────
Location: functions/src/payments/razorpay.ts - verifyPayment()
Issue: Race condition - payment could be processed twice if webhook and client both trigger
Solution: 
  - Wrapped entire booking update in Firestore transaction
  - Re-read booking inside transaction to check current state
  - Check if already paid INSIDE transaction (not before)
  - Prevents race conditions completely

Code:
  await db.runTransaction(async (transaction) => {
    const currentBookingDoc = await transaction.get(bookingRef);
    const currentBooking = currentBookingDoc.data();
    
    // Check if already paid INSIDE transaction
    const isPaid = currentBooking.payment?.status === 'paid';
    if (isPaid) {
      console.log('Payment already processed');
      return; // Idempotent - safe to skip
    }
    
    // Update booking atomically
    transaction.update(bookingRef, updateData);
  });

Impact: ✅ Eliminates race conditions completely

FIX 3: WALLET INTEGRATION (CRITICAL)
────────────────────────────────────
Location: functions/src/payments/razorpay.ts - verifyPayment()
Issue: Technician wallet was NOT being credited after payment
Solution:
  - Credit technician wallet INSIDE same transaction as booking update
  - Calculate technician amount = bookingTotal - platformFee
  - Create wallet if doesn't exist
  - Update wallet if exists
  - Create transaction record atomically

Code:
  if (currentBooking.technicianId) {
    const techWalletRef = db.collection('technician_wallets').doc(currentBooking.technicianId);
    const techWalletDoc = await transaction.get(techWalletRef);
    
    let technicianAmount = bookingTotal - platformFee;
    
    if (techWalletDoc.exists) {
      transaction.update(techWalletRef, {
        availableBalance: admin.firestore.FieldValue.increment(technicianAmount),
        lifetimeEarnings: admin.firestore.FieldValue.increment(technicianAmount)
      });
    } else {
      transaction.set(techWalletRef, {
        availableBalance: technicianAmount,
        lifetimeEarnings: technicianAmount,
        pendingBalance: 0
      });
    }
    
    // Create transaction record
    transaction.set(techWalletRef.collection('transactions').doc(), {
      type: 'credit',
      source: 'booking_payment',
      amount: technicianAmount,
      fee: platformFee,
      referenceId: bookingId,
      paymentId: razorpayPaymentId
    });
  }

Impact: ✅ Technician wallet now credited immediately after payment

    await bookingRef.update({
      'payment.status': 'failed',

  });

FIX 6: PAYMENT RETRY SUPPORT (NEW)
──────────────────────────────────
Location: functions/src/payments/razorpay.ts - canRetryPayment()
Issue: No way to check if payment can be retried
Solution:
  - New function: canRetryPayment()
  - Checks if booking is in awaiting_payment state
  - Checks if payment status is failed or processing
  - Returns boolean + current state info

Code:
  export const canRetryPayment = functions.https.onCall(async (data, context) => {
    const canRetry = currentStatus === 'awaiting_payment' && 
                     (paymentStatus === 'failed' || paymentStatus === 'processing');
    return { success: true, canRetry, currentStatus, paymentStatus };
  });

Impact: ✅ Customers can now safely retry failed payments
