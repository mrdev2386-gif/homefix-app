PAYMENT FLOW CHANGES:
─────────────────────

OLD FLOW (BROKEN):
1. Customer creates booking
2. Payment created before service
3. verifyAndCreateBooking() writes to verified_payments (never creates booking)
4. Booking never created - DATA LOSS

NEW FLOW (FIXED):
1. Customer creates booking → pending_admin_review
2. Admin approves → approved_by_admin
3. Technician accepts → technician_accepted
4. Technician starts service → service_in_progress
5. Technician completes service → awaiting_payment
6. Customer pays via Razorpay → paid
7. Technician wallet credited
8. Customer rates service

SECURITY IMPROVEMENTS:
──────────────────────

1. Amount Validation
   ✓ Amount NEVER comes from client
   ✓ Amount fetched from Firestore (locked pricing)
   ✓ Amount verified against Razorpay payment

2. Signature Verification
   ✓ Razorpay signature verified using HMAC SHA256
   ✓ Invalid signatures rejected
   ✓ Prevents payment tampering

3. Duplicate Payment Prevention
   ✓ Firestore transaction checks if already paid
   ✓ Idempotent operation - safe to retry
   ✓ No double charging

4. Booking Status Validation
   ✓ Payment ONLY allowed for "awaiting_payment" status
   ✓ Prevents payment for wrong bookings
   ✓ Prevents payment for already paid bookings

5. Booking Ownership Validation
   ✓ Verifies booking.customerId === userId
   ✓ Prevents unauthorized payments

6. Technician Validation
   ✓ Verifies technician exists
   ✓ Verifies technician is approved
   ✓ Prevents payment to unapproved technicians

7. Atomic Wallet Crediting
   ✓ Booking update + wallet credit in single transaction
   ✓ No partial updates
   ✓ Consistent state guaranteed
